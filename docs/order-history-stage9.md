# 第9段階：現在の状況と不在の訪問記録

## 表示

受注一覧の「作業結果（訪問日当日）」を「現在の状況」に変更し、当日集計への表示フォールバックを止める。未完了・完了・搬入不可／日延の要対応・キャンセル・不在を現在の受注状態で表示する。既存データの完了判定はSQL側で従来の完了状態・当日の全班完了を参照し、一覧の絞り込みと表示を揃える。

自動更新やポーリングは追加しない。既存の更新・検索・保存後の再取得で最新状態を取得する。絞り込みは「未完了・完了・キャンセル・すべて」を維持し、不在は未完了に含める。

## 不在の操作

- 担当伝票のフッターに「不在」、事務側の結果フォームにも「不在」を追加。
- 初回・不在からの再度の不在は、確認だけで保存できる。保存時の時刻をDBの `SYSDATETIME()` で取得し、端末からは受け取らない。
- 同じ伝票・作業日の全班へ結果を反映。履歴と操作者を既存の結果ログ・受注ログに記録する。
- 受注一覧と担当カードには「不在 MM/DD HH:mm:ss」を表示。担当カードや配車の過去日の表示には、その日の結果の更新時刻を使い、別日の最新時刻と混ぜない。
- 不在は日延と分け、訪問予定日・時間と配車を保持。当日の再訪問が可能。
- 別の要求IDで再度不在を報告すると、新しい訪問記録として履歴を追加。同じ要求IDの再送は時刻や履歴を増やさない。
- 不在の後の完了は通常の完了報告として扱い、訂正理由を要求しない。既存の完了・搬入不可・日延から不在へ訂正する場合は従来どおり理由が必要。
- 不在のまま住所などだけ編集しても不在を解除しない。訪問日を別日に変更した場合は未完了へ戻す。
- 不在を自動で訪問日未定にする処理は入れていない。未処理のまま別日に対応する場合は、日延の報告または事務側の再訪問日登録を使う。

## DB

`database/schema/20261101_order_absence.sql` を開発DBへ適用。受注と受注ログに `outcome_reported_at` を追加し、結果種別と履歴のチェック制約へ `ABSENT` を追加。既存データは変更しない。

受注・結果・ログ・履歴は同一トランザクション、既存のversion排他・担当認可・事務権限・再送抑止を維持する。
