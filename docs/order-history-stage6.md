# 第6段階：事務側の作業結果表示

※後続の伝票単位の報告仕様は `order-history-stage7.md` を参照。件数表示と班単位の報告は同資料の仕様で更新。

## 変更内容

- 既存 `/api/query` の受注一覧に「作業結果（訪問日当日）」を追加。
- 配車画面の伝票カードには当日の結果件数、班の伝票にはその班・作業日の結果を表示。
- 複数班は「完了 1・未報告 1」のように併記し、単一の伝票状態に置き換えない。
- 未配車・訪問日未定の受注には集計対象がないため「—」。未報告は当日の有効な配車に報告がない場合。
- 班の結果表示に理由・備考のツールチップを付与。日時・操作者・過去の報告は既存の受注履歴で確認する。

## 集計条件

`WorkResultSummarySql` は `orders.visit_date` と `daily_crews.work_date` が一致する有効な配車を集計する。結果は配車IDと作業日の両方で照合する。配車解除済み・削除済みの班・過去日の報告は集計しない。日付変更や再配車後に以前の完了を引き継がない。

受注・配車の既存の権限条件、パラメーター、保存処理、version・トランザクション境界は変更しない。参照だけを追加する。新規テーブル・マイグレーションは不要。

## 表示

配車カードは既存のHTMLテンプレートへ `data-field="workResult"` を追加。受注一覧は既存の列定義を使用。状態名・件数の描画は共通JS、色は `/css/common/work-result.css` にまとめる。担当伝票一覧の既存色設定は維持する。

スマホの受注カードは既存の開閉仕様に従い、展開時に作業結果を表示する。一覧・ボードの通常の再検索／再読み込み時に最新の報告を取得し、自動ポーリングは追加しない。

## 検証

- Javaテスト215件：206件成功・既存9件スキップ。
- JavaScriptテスト123件成功。複数班・未報告・理由の安全な文字列表示を追加検証。
- 開発DBで受注一覧（訪問日／登録日）、配車伝票一覧、班別配車一覧の4SQLを実行。
- 読み取り専用のSQLテストデータで、複数班・過去日・解除済み配車の集計を確認。業務データ変更なし。
- ブラウザーでの実画面の表示確認は未実施。

## 未着手

例外報告の確認済み管理、通知、専用絞り込み、自動日付変更・再配車は追加していない。日付変更・再配車は事務側が既存操作で行う。
