# 第7段階：伝票・作業日単位の作業結果

## 決定内容

複数班で同じ現場へ行くため、完了・搬入不可・日延は伝票単位として扱う。同じ伝票でも、別日の訪問へ過去の結果を引き継がない。

## 実装

- 現在の担当者だけが報告可能という認可を維持。
- 報告時点で有効な同じ受注・作業日の配車全班へ、結果・理由・実際の報告者を同一トランザクションで保存。訂正も全班に反映。
- 班IDの昇順に班をロックしてから、受注の割当をロック。取得中に未ロックの班が増えた場合は開き直しを求め、保存しない。
- 報告元の割当version・結果version・作業日を検証し、別の担当者が先に報告した古い画面からの上書きを拒否。
- 既存のBaseSqlRepositoryとversion付きログを使用。反映先の要求IDは報告元UUIDと割当IDから安定して生成し、再送は報告元ログで判定する。
- 業務履歴は報告操作ごとに1件。反映先の各班には既存の結果ログを残す。いずれかの保存や履歴記録が失敗したら全体をロールバック。
- 初回完了は確認だけ。搬入不可・日延、報告済みの訂正には理由が必要。
- 受注一覧と配車カードは件数を外し「完了」「搬入不可」「日延」「未報告」と表示。
- 注文日付や再配車の自動変更、新規テーブル、マイグレーションはなし。

## 範囲

既存の過去の報告は一括変更しない。次の報告・訂正で、その時点の同日有効配車を揃える。報告後に新しく追加した配車への自動転記は今回の対象外。事務側一覧の訪問日当日の参照条件は第6段階と同じ。
