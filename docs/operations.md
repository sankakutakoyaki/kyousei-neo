# 運行・資格・労務管理

## 画面と使い方

既存のメニュー、共通フォーム、一覧、確認ダイアログ、添付機能を利用します。
HTMLは `src/main/resources/templates/fragments/pages/operations/` にあります。

- **運行 → 車両 → 車両一覧**：車両コード、ナンバー、車種、乗車定員、ドラレコ識別情報を登録。
- **運行 → 車両 → 点検予定・実施履歴**：車検・年次点検などの期限、予定日、実施日、走行距離、費用、書類、使用不可期間を登録。
- **運行 → 配車 → 日別編成**：運行日と車両コードを指定し、担当者コードを入力して追加。定員内で複数名登録し、ドライバーを1名指定。前日の編成をコピーできます。
- **運行 → 配車 → 伝票への割当**：既存の訪問日・訪問時間を使用。伝票に車両コードで日別編成を複数追加し、乗車メンバーのコードから現場責任者を指定。1車両で複数伝票を担当できます。受注詳細にも配車への移動ボタンを設けています。
- **運行 → 運転記録**：日・車両・担当者に得点を手入力。未入力と0点を区別。編成変更後も記録の担当者は変わりません。
- **登録 → マスター → 資格種類**：免許・資格・教育等の種類、有効期限の要否、運転免許区分を登録。
- **管理 → 資格 → 保有資格一覧**：担当者コードと資格コードで取得日、有効期限、更新予定日、証番号、書類を登録。従業員詳細から資格名と日付を参照できます。
- **管理 → 労務 → 保険・年金／健康診断**：保険・年金・雇用保険・退職金共済、適用期間、確認日、健康診断日等を管理。住所・生年月日・緊急連絡先等は既存従業員情報を使用。

担当者コードが重複している場合は、既存従業員マスターのコードを整理してください。同じ担当者を同日の別車両へ重複登録できません。基本的に1日固定の編成です。日中の乗換え管理は今回の対象外です。

## 権限

| 対象 | admin・master | leader | staff・user |
| --- | --- | --- | --- |
| 日別編成・配車 | 閲覧・編集 | 閲覧・編集 | PC編集、スマホ閲覧 |
| 車両・点検・運転記録 | 閲覧・編集 | 閲覧・編集 | 閲覧 |
| 資格種類 | 閲覧・編集 | 閲覧 | 閲覧 |

画面制御に加えてAPIでも権限を確認します。資格添付ファイルはURLからの直接取得にも同じ制限を適用します。点検・資格書類は履歴保全のため削除せず、更新版を追加します。

## 履歴と既存データ

各登録は本体と `_log` を同一トランザクションで保存します。更新番号により他画面からの上書きを防ぎます。削除は無効化として記録します。

日別編成の変更は、影響する未完了伝票を確認してから保存します。伝票の現場責任者を外す場合は先に責任者を変更します。完了済み伝票には保存時の車両・乗車メンバーを残し、後の日別編成変更を反映しません。

旧配送・工事担当者と変更ログは削除せず、配車詳細で旧割当を参照できます。車両との関係を推測して移行しません。未完了伝票は日別編成を登録したうえで新しい配車画面から割り当ててください。旧画面の保存APIは停止しています。

訪問日を変更した伝票には配車日不一致を表示します。変更後の日付の編成で割り当て直してください。免許と点検期限の表示は登録内容の確認用で、車種ごとの運転可否を自動判定するものではありません。

## DB適用と反映

SQL Serverを対象とします。実際のDBへの適用・接続検証はこの変更では実施していません。

1. アプリの書込みを停止し、DBと添付ファイルをバックアップ。
2. 未適用なら `database/schema/20260901_create_attachments.sql` を適用。
3. 未適用なら `database/schema/20260913_create_order_dispatch.sql`、続いて `20260913_add_order_dispatch_log.sql` を適用。
4. `database/schema/20260913_create_operations.sql` を適用。
5. 新しいアプリをビルドして起動。以下の確認をテスト環境で行ってから本番へ反映。

新SQLは未作成テーブルのみを作成し、既存の受注・従業員・旧配車を削除しません。既存テーブルの定義修復は行わないため、途中で独自変更した環境は定義の差異を確認してください。

確認項目：車両と3名以上の編成、同日の二重登録拒否、1伝票への複数車両、現場責任者、編成変更時の影響確認、完了伝票の過去メンバー保持、得点の未入力／0点、資格書類の権限制御、スマホの管理者編集と一般ユーザーの閲覧、本体とログの同時保存。SQL Server上での外部キー・ロールバック・同時更新の確認も必要です。

ドラレコファイル取込と作業員名簿のExcel／PDF出力は今回実装していません。

## 2026-09-15：配車ボードと担当営業所

配車は運行日を選び、左側の車両・日別編成、右側の当日伝票を表示します。
伝票から車両、車両から伝票のどちらのドラッグでも追加できます。スマホ・キーボードでは両側の「選択」ボタンを使用します。
操作後の確認画面で現場責任者を指定して保存してください。既存の車両を残して追加するので複数台配車が可能です。解除は伝票の詳細で車両を外して保存します。
未編成車両・完了伝票はドラッグ対象になりません。日付の変更時は一覧を再読込します。

保有資格・更新予定・期限切れは「保有資格一覧」の状態欄でまとめて確認できます。更新予定は90日以内の期限・更新日と予定超過分です。

受注と配車の担当営業所は、荷主側の支店とは別の自社営業所です。新規受注の担当営業所、受注一覧、配車、出退勤管理の初期選択は、ログインアカウントに対応する有効な従業員の所属から取得します。所属不明・重複などで特定できない場合、検索は「すべて」、新規受注は「未設定」です。これは検索の初期値であり、他営業所へのアクセス制限ではありません。

今回の版を起動する前に `database/schema/20260915_add_order_own_office.sql` を適用してください。`orders` と `orders_log` に `own_office_id` を追加します。既存受注・過去ログの営業所は推測して埋めません。既存受注は「未設定」または「すべて」で検索し、受注詳細で担当営業所を指定してください。実DBへの適用はこの作業では行っていません。

## 2026-09-16：車両の営業所

車両画面は検索文字入力を営業所コンボへ変更。「全て」と各自社営業所を選べます。
所属営業所を初期選択し、本社（office_id=1000）と所属を特定できない利用者は「全て」です。
新規車両では営業所を登録できます。既存車両は未設定のまま保持し、「全て」から詳細を開いて営業所を設定してください。
ボタンは既存の共通部品を使用します。削除はチェックした車両をまとめて無効化し、配車等により削除できないものが含まれる場合は全件ロールバックします。取得は選択行（選択がなければ表示中の全件）のCSVです。
起動前に `database/schema/20260916_add_vehicle_own_office.sql` を適用してください。車両本体と変更ログに営業所を追加します。実DBには未適用です。

## 配車画面の共通構成

配車の左右一覧は `createCrudPage` → `PageController` → `DataTable` / `TableModel` で管理します。
`pages/operations/dispatch/columns.js` が表示項目を定義し、`repositories/operations/DispatchRepository.js` が通信を担当します。
左右の検索は同一の取得結果を共有し、キーワード・未配車の絞り込み、並び替え、50件超の追加表示には共通テーブル処理を使用します。
フォームは `dispatch/dispatchForm.js` の `FormController` をページへ登録し、保存後は共通の検索アクションで両一覧を更新します。
`dispatchBoard.js` は描画済みの行へのドラッグ・選択操作の追加だけを担当します。
共通側の追加は初期取得を待機できる `autoLoad`、描画後の `onRendered`、古い検索応答の破棄です。未指定の画面は従来どおり初期取得・描画します。この構成変更にDB変更はありません。
