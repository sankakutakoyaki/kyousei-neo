# 伝票履歴 第2段階：受注詳細の履歴タブ

## 変更内容

受注詳細の既存タブに「履歴」を追加。既存のcreateOrderPage / FormControllerの開閉処理から、data-*で指定したOrderHistoryListを初期化する。添付管理と同様の独立した表示部品とし、共通イベント・フォーム・保存処理は変更しない。

- 履歴タブを開いた際に第1段階のOrderRepository.findHistoriesを呼び出す。新規・未保存OCR候補はAPIを呼ばず保存後に確認する旨を表示。
- 受注登録／受注保存、日時、操作者を新しい順で表示。取得上限100件に合わせ、最後の履歴IDを使って「続きを表示」。100件ちょうどの場合は次の空ページ取得で追加表示を終了する。
- 「更新」は先頭から取得し直す。読込中はボタンを無効化して二重要求を抑止。失敗時は既存の表示・カーソルを維持し再試行できる。
- タブを開くまで履歴取得を待機するため、履歴取得失敗やDBの履歴テーブル未準備によって受注詳細を開けなくなることはない。ただし受注保存には第1段階のDDLが必要。
- FormControllerの既存canApplyと部品の世代番号で、閉じた後・別受注を開いた後・画面が外れた後の古い応答を破棄。既存明細取得後にもcanApply確認を追加し、古い明細応答による上書きを抑止。
- 日時は既存formatDateを再利用。サーバー由来の操作者名などはtextContentで表示。新しいタブはキーボードのEnter/Spaceでも開ける。履歴操作ボタンはtype=buttonで、保存や入力変更には含まれない。
- CSS追加はすべてrem単位。履歴タブはスマートフォンの閲覧専用モードでも参照可能。新API・権限・依存パッケージ・DB変更は追加していない。
