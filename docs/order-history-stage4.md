# 伝票履歴 第4段階：配車操作の記録

## 対象と実装

現行配車画面が呼び出すDispatchAssignmentHandlerの5操作を対象とする。

| 操作 | イベント | 表示 |
|---|---|---|
| CREATE | DISPATCH_CREATED | 配車を登録 |
| MOVE | DISPATCH_MOVED | 配車を移動 |
| REMOVE | DISPATCH_REMOVED | 配車を解除 |
| RESET | DISPATCH_RESET | 配車を一括解除 |
| REORDER | DISPATCH_REORDERED | 訪問順を保存 |

各割当の更新・既存ログ保存直後にOrderHistoryRepository.recordDispatchを呼ぶ。既存の@Transactional、班の昇順ロック、versionによる排他を維持。履歴側もMANDATORYで同一トランザクションへの参加を必須にし、失敗は操作全体へ伝播する。一括解除・並び替えの途中で失敗した場合も、同じ操作の他の更新を含めてロールバックする。

order_id、dispatch_assignment_id、dispatch_versionはリクエストを信用せず保存後のDB行から取得する。受注versionはその時点の受注バージョンを記録するが、配車の比較には使用しない。

## スキーマ変更

`database/schema/20261031_add_order_dispatch_histories.sql` を追加した。第1段階の作成SQLの後、アプリ更新前に適用する。

- order_historiesにnullableのdispatch_assignment_idとdispatch_versionを追加。
- 受注ID/versionの全イベント共通の一意制約を、配車参照なしの行に限るフィルター付き一意索引へ変更。これにより、受注を編集しなくても同一受注versionで複数回の配車操作を記録できる。
- 配車割当ID/versionにもフィルター付き一意索引を追加し、同じ配車更新の二重記録を抑止。
- イベント種別と参照列の組合せをCHECK制約で検証する。既存の受注履歴は保持。
- 追加列を同一SQLバッチで参照するため動的SQLでコンパイルを分け、全DDLをトランザクションで実行する。再適用可能。

開発DB NeoDBには本SQLを適用済み。受注・配車の既存データは変更していない。他環境へ展開する場合もアプリ更新前に適用すること。旧アプリの受注履歴追加と互換性を保つ。

## 参照・表示

既存orderHistoryListの権限制御・カーソル方式・最大100件を維持。dispatch_assignments_logを割当ID、受注ID、割当versionで参照し、変更前はversion - 1に限定する。受注情報ログとの比較は受注イベントだけに適用する。

表示は配車先（班ID）と訪問順。登録・解除は未設定との変化、移動・並び替えは前後を表示する。車両名を後から変更した場合に過去表示が書き換わらないよう、現在のdaily_crewsやvehiclesの名前を過去の事実として結合しない。車両名・班員の履歴名称の復元は別段階とする。

前後のログが欠落・重複していればイベントだけ残し、変更内容を確認できない旨を表示する。並び替えAPIは既存どおり全送信行のversionを進めるため、順序が同じ行も「訪問順を保存」として記録し、配車先・訪問順に変更がない旨を表示する。

## 検証

- Java: 204件中195件成功、既存9件スキップ、失敗・エラー0。
- JavaScript: 114件すべて成功。
- 既存5操作のテストに記録確認を追加。並び替えの複数行の更新後記録、認証済みeditorの引継ぎ、更新失敗時の記録抑止、履歴失敗の例外伝播を確認。
- JDBC接続をモックしたトランザクションテストで、配車・ログ更新後の履歴失敗が同一接続のrollbackになりcommitしないことを確認。
- SQLテストで、割当ID/受注ID/正確なversionの照合、既存権限・ページングの維持を確認。
- フロントテストで、5種類のラベル、登録・移動・解除・一括解除の前後値、欠落・重複ログ、変更なしの並び替え、既存差分描画の再利用を確認。
- 開発DBの実スキーマを確認後、5種類の履歴追加SQLと拡張した参照SQLを同一トランザクション内で実行。各イベントの取得と一意索引による二重登録の拒否を確認し、検証用履歴は全件ロールバックした。配車・受注自体の更新はしていない。

ブラウザー経由で配車操作から履歴表示までの一連の動作は未確認。再ビルド・アプリ再起動後、画面を再読み込みして登録・移動・解除を行い、受注詳細の履歴を確認する。

## 今回の対象外

- 班の車両・班員そのものの変更、班削除などDailyCrewHandler側の操作。
- 現行配車画面から利用されていない汎用dispatchAssignmentSave / dispatchAssignmentDeleteByIds経路（登録は残している）。
- 担当伝票専用画面への履歴タブ追加、車両名・班員の当時の名称復元。
- 搬入不可・日延・完了・直収、PDF別登録経路、商品・作業の単独操作、過去の配車ログのバックフィル。
